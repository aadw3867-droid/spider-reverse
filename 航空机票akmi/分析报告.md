# T'way Airlines Akamai Availability Collector

## Scope

Target: `https://www.twayair.com/` and its redirect target `https://www.trinityairways.com/`.

The requested outcome is browser-free retrieval of one-way flight availability and fares. Python `curl_cffi` owns all live HTTP, cookies and queue state; IV8 executes the current Akamai collector in an isolated process and returns same-origin XHR intent to the Python parent.

## Implemented Workflow

`main.py` contains the current collector scaffold and protocol steps:

1. Follow the landing redirect in one Python-owned `curl_cffi` Session.
2. Read the current NetFunnel, pixel and randomized collector script URLs from the landing HTML.
3. Enter NetFunnel (`H_LandingPage`), run the current landing collector in IV8 with a synchronous Python XHR bridge, and complete the queue ticket before `/app/main`.
4. Classify `/app/main` as denied, challenge/degraded, or trusted/full before applying branch-specific checks; run a declared main-page collector only when present.
5. Construct the final one-way form fields from the live page and requested ICN→KIX/date values, run `chkSaleRoute`, then the user-authorized `chooseItinerary` and `layerAvailabilityList` availability requests.
6. Parse flight number, departure/arrival, date, duration, stops, fare class, booking class, currency, price, seat count, sold-out state and baggage.

Default query is ICN→KIX, host date + 7 days. Override with `--departure`, `--arrival`, `--date`; process-wide request cap is controlled by `--max-requests` / `AKAMAI_MAX_TOTAL_REQUESTS`. No rotating cookies, queue tickets or sensor payloads are hardcoded or persisted.

## Acceptance

Local parser tests cover a non-empty and sold-out fare row. Live acceptance requires all of:

- landing and sensor response cookie continuity;
- NetFunnel enter/complete in the observed order;
- `/app/main` admitted on this egress;
- `chkSaleRoute` is not explicit `success:false`;
- choose and availability responses are business responses, not Access Denied or SBSD/privacy shells;
- parsed flight/fare records are non-empty.

An empty itinerary is classified as inventory/date state only after the security/queue chain succeeds. A `200` alone is not acceptance.
