# Adidas HK Akamai 协议恢复报告

## 目标

目标站点为 `https://www.adidas.com.hk/`，交付目标是脱离浏览器获取商品信息。

## 已确认的 Akamai 证据

- 入口返回 HTTP 403 和 Adidas security issue 页面。
- 页面加载随机多段 challenge 脚本 `/CAcWH/.../DUMT1AY`。
- challenge 脚本 SHA-256：`553e4f62200be416a06c91dcb9a5980c7b2be01609899c600b2dcbc3cb3713df`。
- 浏览器 Cookie 家族包含 `_abck`、`bm_s`、`bm_sz`、`bm_so`、`bm_lso`、`ak_bmsc`。
- challenge XHR POST 发往同一个随机路径，JSON 顶层字段为 `body`。
- 浏览器样本 POST body 长度为 3176 字节。
- 浏览器样本响应为 HTTP 200 空体，响应含 `Server-Timing: ak_p`，并更新 `bm_s`。

## NV8 运行结果

NV8 可以在 Edge-like Realm 内执行保存的 Adidas challenge 脚本，并通过
`networkRelay` 把 XHR 交给 Python/curl_cffi Session。当前运行生成的 challenge
POST body 约 4563 字节，明显不同于 Firefox 样本的 3176 字节。Python relay
实际收到 HTTP 200 空体响应，响应含 `ak_p` 和 Akamai trace，但没有形成可继续
进入商品页的有效状态。

## 当前验收状态

当前不能声明商品 collector 已完成。原因有两层：

1. 同一出口的真实 Firefox 入口也返回 Adidas HTTP 403。
2. NV8 Edge profile 生成的 body 与 Firefox 正样本长度不一致，且 relay 响应没有
   形成下一阶段业务放行。

这符合 Akamai 的出口信誉/传输一致性阻塞分支。HTTP 200 challenge 响应和已有
Cookie 名称不能作为成功依据。

## 2026-10-24 纯协议实现复核

需要更正此前“已经过 Akamai”的表述：`main.py` 当前只用
`curl_cffi impersonate=firefox135` 请求列表/Quick View，并由 Session 自动
接收服务器 Cookie。它没有实现或独立生成 Akamai sensor、`_abck` 或 Cookie
状态机，因此不能据此声称完整纯协议 Akamai 已完成。

用户已批准在隔离 NV8 中执行当前轮换 challenge，目标域限制为
`adidas.com.hk`，只记录 Cookie 名称、长度和哈希前缀。预算耗尽前的单轮尝试：

- 首页：`403 text/html`，同一 Python Session 收到 `_abck`、`bm_s`、`bm_so`、`bm_sz` 等服务器 Cookie。
- Challenge script：`200 application/javascript`，当轮 SHA-256 为
  `9da6548845f42c921baaa9a6722b6eef119953fe171ec411baf2ef51ed4148e4`。
- NV8 执行生成了一个 sensor POST，body 长度 `3843`，但其 outcome 为
  `replay-miss:missing`；Python Session broker 实际收到 `0` 个请求。
- 随后同 Session 商品列表返回 `200 text/html`、48 个商品，但由于 sensor
  没有通过 Python broker 发出，不能把这次 `200` 作为 Akamai sensor 协议验收。
- 所有 Cookie 值都未落盘；只记录名称、长度、哈希前缀。
- 总 HTTP 请求未超过本轮批准的 4 次上限。

当前实现文件：

- `js_reverse_cache/akamai/run_same_session.py`：Python-owned Session、动态脚本 hash 记录、单轮编排和 4 请求限制。
- `js_reverse_cache/akamai/run_current_challenge.mjs`：隔离 NV8 challenge 执行和请求摘要。
- `js_reverse_cache/akamai/relay_helper.py`：NV8 JSONL 到 loopback Session broker 的桥。
- `js_reverse_cache/akamai/test_relay_offline.py`：本地假响应协议测试，已通过；不产生目标网络请求。

最初 NV8 `networkRelay` 子进程没有命中 Python-owned broker；离线 NV8 测试使用了不正确的 Windows helper 路径。改为 Node `fileURLToPath()` 并显式传 loopback 端口后，本地 mock 验收为 `outcome=service-worker`、响应 `relay-ok`。

离线 relay 测试文件：`js_reverse_cache/akamai/test_nv8_relay_offline.mjs`、
`js_reverse_cache/akamai/test_relay_offline.py`；均不访问 Adidas。

## 2026-10-24 修复后 live 纯协议链路

用户批准额外最多 12 个 Adidas HK HTTP 请求；集成 `main.py --akamai-protocol` 实际使用 5 个：

- 首页 `403`，同一 Python Session 获得初始 Akamai Cookie。
- 当轮 challenge JS SHA-256：`f4f6388954c14cc96a7c9c0562c65bda8c4a06b012ec55ac4ca44c970eca6e17`。
- NV8 sensor POST body `4560` 字节，经 loopback broker 进入同一 Python Session，收到 `HTTP 200`、空体及 `Server-Timing: ak_p`。
- `Search-UpdateGrid` 返回 `200 text/html`，page `1`，解析到 `48` 个商品。
- 同 Session Quick View 商品 `KK0633` 返回 `200 text/plain;charset=UTF-8`，JSON product ID 匹配。
- Cookie 原值未落盘；只记录名称、长度和哈希前缀。

这证明当前 challenge 执行路径能生成并递交 sensor body，服务器更新会话 Cookie 后，同一 Python Session 可取商品列表和详情。它不是通用手写 `_abck` 公式；每轮 challenge 会变化，NV8 执行当轮脚本，Python 负责全部真实 HTTP egress。

## Akamai 传输与浏览器对照结果

本轮使用托管 Camoufox Firefox 135 和同一出口完成对照：

- 首页首次仍返回 `403`，随后加载随机 challenge 脚本并 POST 同一路径。
- Challenge POST：`HTTP 200`、`Content-Type: application/json`、请求 body `3171` 字节、响应空体，响应含 `ak_p` 和 `x-akamai-trace-id`。
- challenge 完成后，`Search-UpdateGrid` 返回 `HTTP 200 text/html;charset=UTF-8`，页面包含 48 个商品。
- 浏览器业务请求响应含 `x-firefox-spdy: h2`，且有 `ak_p`；浏览器 UA 为 Firefox 135，平台为 Windows，时区为 `Asia/Shanghai`。
- 浏览器 Cookie 转换由 HTTP `Set-Cookie` 完成，未观察到 JS `document.cookie` 写入；关键族包括 `_abck`、`bm_s`、`bm_sz`、`bm_so`、`ak_bmsc`、`akacd_Generic_Prod_PR_CommLean`。

Python 侧已将请求传输基线改为：

```text
curl_cffi impersonate=firefox135
Mozilla/5.0 (Windows NT 10.0; Win64; x64; rv:135.0) Gecko/20100101 Firefox/135.0
Accept-Language: en-US,en;q=0.5
Accept-Encoding: gzip, deflate, br, zstd
Upgrade-Insecure-Requests: 1
```

改动后验证结果：

- 同一页连续两次：`HTTP 200`、业务页、每页 48 条、无 challenge。
- 连续两页：页面号 `1/2`，总商品 `96`，唯一商品 ID `96`。

本轮结论：暂时不需要用户单独提供 TLS。当前关键因素是 TLS/HTTP2 impersonation、UA 版本、语言/压缩头和 Akamai Cookie 生成时序必须保持 Firefox 135 一致。当前出口已经能完成业务商品请求，后续只需继续验证多页/长会话稳定性；若再次出现浏览器与 Python 同时 Access Denied，再切换出口。
