# Adidas HK Akamai Product Workflow

This skill documents the browser-free Adidas Hong Kong product workflow in
`main.py` and `js_reverse_cache/akamai/run_same_session.py`. Python owns every
live HTTP request and one `curl_cffi` Session; NV8 runs the current site-served
challenge script in an isolated Realm and sends its fetch/XHR through a bounded
loopback relay into that same Session.

## Current Implementation

The active implementation uses Python and `curl_cffi`:

```python
requests.Session(impersonate="firefox135", default_headers=False)
```

The current Akamai path uses NV8 for the dynamic challenge sensor because the
sensor payload is generated by the site's current script. This is not a
hand-derived or hardcoded `_abck` formula. Never hardcode rotating sensor
bodies or Cookie values. Python remains the only live HTTP egress; NV8's
networkRelay must be connected to the Python-owned Session broker.

## Transport Contract

Keep the transport tuple coherent:

```text
impersonate: firefox135
User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64; rv:135.0) Gecko/20100101 Firefox/135.0
Accept-Language: en-US,en;q=0.5
Accept-Encoding: gzip, deflate, br, zstd
Upgrade-Insecure-Requests: 1
```

Use one `curl_cffi` session for homepage/challenge fetch, sensor POST/CPR calls,
and all subsequent list or detail requests. Never hardcode `_abck`, `bm_s`,
`bm_sz`, `bm_so`, or other dynamic Akamai cookies. Let each HTTP response update
the same session jar before the next sensor stage. Audit values only as
name/length/hash metadata. A successful `200` sensor response with an empty body
is not itself admission; require the subsequent business response.

An optional `ADIDAS_COOKIE` environment variable may seed a session, but a
fresh server-issued cookie state is preferred. `ADIDAS_IMPERSONATE` and
`ADIDAS_USER_AGENT` can override the defaults only when the replacement values
are kept mutually consistent and are supported by fresh evidence.

## Business Endpoints

### Product list

Use:

```text
https://www.adidas.com.hk/on/demandware.store/Sites-adidas-HK-Site/en_HK/Search-UpdateGrid
```

Build parameters with `build_search_url`:

```text
cgid=men
pmin=0.01
start=0, 48, 96, ...
sz=48
selectedUrl=<the same endpoint and query without selectedUrl>
```

The response is server-rendered HTML. Use `parse_product_html`; do not expect
JSON. A valid business response has `text/html`, product cards, a page number,
and product IDs. The parser extracts product ID, model ID, name, price, status,
category, product type, detail URL, images, badges, gender division, and color
variants. Deduplicate pages by `product_id`.

### Product detail

The active detail endpoint is the Quick View JSON endpoint:

```text
https://www.adidas.com.hk/on/demandware.store/Sites-adidas-HK-Site/en_HK/Globale-Cache
  ?remoteIncludeUrl=Product-ShowQuickView&pid=<PRODUCT_ID>&ajax=true
```

Warm the same session with one successful product-list request before detail
requests. `fetch_product_detail` accepts the `200` response even when the
content type is `text/plain;charset=UTF-8`, then parses its JSON body.

`parse_product_detail` normalizes:

- product ID, name, brand, type, canonical ID, color
- sales price, currency, and formatted price
- `available`, `readyToOrder`, `online`, and availability
- color-level stock entries
- variation attributes and size values
- size label, value, selectable state, selected state, SKU/`attID`, and URL
- zoom, large, and small images
- short/long descriptions and product bullets
- promotions, size chart fields, and quantity limits

The direct PDP URL and a bare `Product-Variation` URL may take a different
Akamai branch or require a concrete size. Do not discard the Quick View result
because the direct PDP is `403`; classify each endpoint independently and use
the endpoint that returns the required business data.

## Challenge And Success Classification

For every response, record:

```text
status
content_type
body_length
challenge
business_page or detail presence
cookie names
page number or product ID
```

Treat `403`, `429`, the Adidas security issue text, or a response without the
expected business payload as a challenge/degraded result. Treat a response as
business success only when the expected product HTML or detail JSON is present.
Do not call an empty challenge `200` a successful product response.

The list/detail acceptance test is:

```text
list response: HTTP 200 + HTML + non-empty product cards
detail response: HTTP 200 + JSON product object
no challenge flag on the accepted response
product IDs and detail IDs match
detail includes price and variation/availability fields when the product has them
```

For a multi-page run, require continuous page numbers, successful business
responses, and unique product IDs after deduplication. For a detail batch,
require every requested ID to return a matching `product.id` and no challenge.

## Akamai Runtime Path

Run the browser-free collector with:

```powershell
python main.py --akamai-protocol
```

The orchestrator:

1. Starts a Firefox 135 `curl_cffi` Session and requests the homepage.
2. Extracts the current external challenge URL and downloads its script in the
   same Session. It records the script SHA-256 and executes only the current
   response; never reuse a stale captured script as if it were current.
3. Executes the script in an isolated NV8 Realm. NV8 itself opens no sockets.
4. Relays matching origin requests to the Python-owned Session through a
   localhost JSONL broker, preserving response Set-Cookie transitions.
5. Fetches `Search-UpdateGrid` and one product's Quick View detail in that same
   Session and parses both into structured data.

The request cap is explicit in `run_same_session.py`. Keep it bounded; if the
site requires more sensor/CPR stages, stop at the cap and request an increased
budget instead of retrying or rotating sessions. Sensor body length can vary by
challenge version and execution environment, so treat body hashes and lengths
as evidence for a run, not constants.
