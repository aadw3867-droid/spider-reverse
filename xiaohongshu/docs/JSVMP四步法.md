# JSVMP 纯算四步法（以小红书 mnsv2 为例）

> 给“看不懂插桩、觉得纯算很难”的自己的一份笔记。
> 结论先放这儿：**JSVMP 纯算不是把算法逆向成人能读的源码，而是黑盒调用它自带的解释器。**

---

## 0. 一句话总览

页面里有「一坨数字数组」+「一个循环解释它的函数」。
你要做的不是读懂那坨数字，而是：

```
① 找到解释器入口
② 找到目标函数的 字节码位置(pc) + 长度(len)
③ 还原它运行时的“环境”（变量/子函数放哪）
④ 直接 CALL 解释器，拿到返回值
```

难点只有 ③。

---

## 1. JSVMP 到底是什么

把它想成**一个小 CPU**：

- `__$c`：一大坨数字数组 = **机器码（字节码）**；
- `_0x1233dd`：一个函数 = **CPU 的解释器**，按 `pc`（程序计数器）逐条执行指令；
- 所以 “mnsv2 函数” 不是普通 JS 函数，而是 **一段机器码 + 一个作用域（闭包）**。

解释器大致长这样（签名以小红书为例）：

```js
function _0x1233dd(code, pc, len, args, env, thisVal, fn, mode) {
  // 读 code[pc] -> switch 分发 -> 操作一个栈
}
```

外层还有一个分发器 `_0x31ad27`，其中 `case '5'`：

```js
return _0x1233dd(...)[1];   // 下标 1 才是真正的返回值
```

## 2. “插桩”到底是什么意思

插桩不神秘，就是**在代码里塞一句话去偷看**。常见三种，本质一样：

| 方式 | 怎么用 | 特点 |
|---|---|---|
| 断点 Breakpoint | DevTools 点行号，执行到就停 | 手动、慢，看变量最直观 |
| 日志点 Logpoint | 右键行号 → Add logpoint，填 `pc,len,args` | 不暂停、自动打印，**最推荐** |
| 代码插桩 | 改源码字符串，在锚点后拼一句 `global.xxx=...` | 自动化、可搬到 Node |

> “JSVMP 要插桩” = 在 CPU 执行时，偷偷记录它读了哪条指令、传了什么参数。

---

## 3. 四步法

### ① 找解释器

浏览器全局搜 `__$c`（那坨大数组），往上找一个 `while` + 巨大 `switch` 的函数，就是解释器。

### ② 找目标函数的 pc / len

在解释器入口打 **logpoint**：`pc, len, args.length`，然后在页面上触发一次签名，控制台会冒出一条：

```
pc=27188  len=26  args=[c,u,p]
```

=> 锁定：mnsv2 从 `27188` 开始，长 `26` 字节，3 个参数。

> 不知道也能暴力找：在“定义函数”的指令处记录所有 `[start,end]`，挨个调用试。

### ③ 还原环境（唯一的坑）

mnsv2 执行时要用常量和子函数，它们不在全局，在 VM 的“池子”里。小红书这次：

- 顶层函数 `_b980`（`start=12780`）身上的属性 `ΙIΙ`（码点 399/49/399）里是 **133 项 pool**（第 35 项起是函数）；
- mnsv2 要的环境形状：

```js
env = { 0: globals, d: 2, $2: self, $0: globals, $1: pool, length: 1 }
```

`globals` 是 26 槽数组。照抄形状即可：

```js
const wrapper = { 0: G, d: 2, $2: globalThis, $0: G, $1: pool, length: 1 };
```

### ④ 直接调用解释器

```js
__CALL(__$c, 27188, 26, [c, u, p], wrapper, globalThis, null, 0)
// => "mns0201_xxxxxxxx..."  (200 字符)
```

全程没“看懂算法”，只是让它的 CPU 替我们跑那 26 字节机器码。

## 4. 插桩是怎么塞进去的（代码插桩真实写法）

在源码里找一段固定表达式当“锚点”，用字符串替换在它后面插代码：

```js
const anchor = '_0x425731=_0x4d21fc[_0x5edc27(0x79)](_0x254e53,_0x30754b,_0x415185);';

code = code.split(anchor).join(
  anchor +
  // 记录每个函数定义区间 [start,end]
  'global.__DEFS=global.__DEFS||[];' +
  'global.__DEFS.push([_0x415185+4,_0x425731-2]);' +
  // 暴露解释器入口
  'global.__CALL=_0x31ad27;'
);
```

`eval(code)` 之后，`global.__CALL` 和 `global.__DEFS` 就到手了。
这就是“代码插桩”的全部。

---

## 5. 为什么要补一点环境

VM 执行时会摸几个浏览器全局，只补被读到的即可：

- `__bc`（客户端指纹，7558 hex）作为全局传入；
- `cookie` 里的 `a1` / `websectiga` / `webId` 会被读；
- `webSsk` 以 `localStorage.webSsk` 形式注入；
- `window` / `self` / `document.cookie` / `crypto` / `TextEncoder` 做最小 shim；
- 坑：Node 里 `navigator`/`performance` 是只读 getter，`'use strict'` 下直接赋值会抛错，必须用
  `Object.defineProperty`。

---

## 6. 为什么都说小红书“简单”

- 解释器就是一个大 `switch`，不是疯狂的控制流平坦化；
- 字节码是**明文数组**，不需要还原；
- 字符串只是 XOR 编码，好解；
- 目标函数很短（26 字节），参数就 3 个；
- 没有 WASM、没有多层 VM、没有强反调试。

对比真正难的：指令集自定义 + 控制流平坦化 + 反调试 + 多层嵌套 VM + WASM。

## 7. 明天早上照着练（复现清单）

1. 打开 `assets/mnsvm.js`，先只找 `__$c` 和解释器函数，确认能正确定位；
2. DevTools 在解释器入口打 logpoint，打印 `pc,len,args`，触发签名，看到 `27188/26`；
3. 跑 `node mns_runner.js`，看它「插桩 → 取 pool → 调用」的完整代码（约 100 行）；
4. 改一个参数（比如把 `[c,u,p]` 换成别的），观察输出变化，理解“黑盒调用”；
5. 看 `xhs/signer.py` 怎么把 `x3` 拼进 `x-s`。

### 术语表

| 术语 | 人话 |
|---|---|
| JSVMP | JS 虚拟机保护（字节码 + 解释器） |
| 字节码 / `__$c` | 那坨数字数组，相当于机器码 |
| pc | 程序计数器，当前执行到第几条指令 |
| 解释器 | 那个大 switch 函数，负责执行字节码 |
| 闭包环境 env | 函数运行时要用的变量/子函数所在的“数组” |
| 池 pool | VM 存放常量与子函数的容器 |
| 插桩 | 在代码里塞打印/记录，观察运行状态 |
| logpoint | 不暂停的断点，只打印 |

### 相关文件

- `assets/mnsvm.js` —— 抠出的解释器 + 字节码（只读核心）
- `mns_runner.js` —— 一次性驱动（插桩 + 取 pool + 调用）
- `mns_worker.js` —— 常驻 worker（高并发）
- `xhs/mns.py` —— Python 侧 worker 池
- `xhs/signer.py` —— 组装 x-s

## 8. 心态

卡住不是笨，是缺“四步法”。
小红书这关过了，其他站点基本就是同一套四步法换个壳：
**找解释器 → 找函数边界 → 补闭包环境 → 黑盒调用**。
